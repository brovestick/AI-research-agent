深度研报 $ARGUMENTS

参数格式：公司代码_简称（如 688102_斯瑞新材）

---

## 前置条件

公司目录 `companies/{代码}_{简称}/` 已存在，`raw/broker_reports/` 中已放入至少一份券商研报 PDF。

---

## 处理流程

### 1. 定位公司目录与 PDF

```
companies/{代码}_{简称}/raw/broker_reports/
```

列出目录下所有 PDF 文件，**跳过文件名以 `（已处理）` 开头的文件**。对每份待处理 PDF 执行步骤 2-4（串行处理，一份完整做完再做下一份）。

### 2. 调用 broker_rpt_extract.py 提取 JSON

```bash
cd research_agent && /opt/anaconda3/bin/python3 tools/broker_rpt_extract.py "<pdf_path>" --out "<json_out_path>"
```

JSON 保存到 `processed/broker_reports/{文件主干名}.json`。

文件主干名 = PDF 文件名去掉 `.pdf` 后缀（如 `华泰证券-斯瑞新材-深度研究.pdf` → `华泰证券-斯瑞新材-深度研究`）。

### 3. Read JSON，转换为 MD

Read 步骤 2 输出的 JSON 文件，将结构化数据转换为可读 Markdown，写入 `processed/broker_reports/{文件主干名}.md`。

MD 格式要求：

```markdown
---
date: {publish_date}
type: broker_report
report_type: {report_type}
broker: {broker}
source: {source_file}
---

# {company_name}（{ticker}）— {report_type_cn}

**发布日期**：{publish_date} | **券商**：{broker} | **分析师**：{analyst}
**评级**：{rating} | **目标价**：{target_price}元

## 核心观点

{investment_thesis / key_takeaway}

## 首页摘要

{将 first_page_summary.key_points 逐条展开为散文段落}

## 增长驱动

{将 growth_drivers 逐条展开，每条包含 driver + logic + growth_estimates}

## 业务结构

{将 business_segments 展开为表格或段落}

## 竞争格局

{competitive_landscape + competitive_advantages}

## 盈利预测与估值

{earnings_forecast + valuation_methodology，如有}

## 风险提示

{key_risks 逐条}
```

根据 report_type 灵活调整章节：
- **first_coverage / deep_dive**：包含业务结构、增长驱动、竞争格局、资本配置、估值方法
- **earnings_review**：侧重财务数据、业绩驱动因素、业务拆分、盈利预测更新
- **event_review**：侧重事件摘要、影响分析、预期差判断

report_type 中文映射：first_coverage→首次覆盖 | deep_dive→公司深度 | earnings_review→业绩点评 | event_review→事件点评

所有数据标注溯源：【来源：{source_file}，broker_rpt_extract】

### 4. 标记已处理

每份 PDF 的 JSON + MD 都写入成功后，将原始 PDF 重命名，在文件名开头添加 `（已处理）`：

```
华泰证券-斯瑞新材-深度研究.pdf → （已处理）华泰证券-斯瑞新材-深度研究.pdf
```

### 5. 清理

处理完所有 PDF 后，列出已生成的文件清单（JSON + MD）及已标记的原始 PDF，确认无遗漏。

---

## 执行纪律

1. **串行处理**：一份 PDF 完整做完（extract → JSON → MD）再处理下一份
2. **立刻写入**：`broker_rpt_extract.py` 产出 JSON 后，立刻 Read JSON 并 Write MD，不攒批
3. **不重新提取**：JSON 已包含全部结构化数据，转 MD 时只做格式转换，不回头读 PDF
4. **MD 服务于下游**：MD 文件将被 `merge_texts()` 读取并注入 `/撰写报告` 流水线，内容应紧凑、信息密度高，避免冗余修饰
