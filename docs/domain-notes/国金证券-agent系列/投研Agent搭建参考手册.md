## 三、核心能力模块

### 3.1 RAG检索增强

**应用场景**：
- 新闻热点检索与点评
- 研报观点提取
- 公司公告解析

**实现要点**：
```
1. 文档切分：使用"通用"或"父子分段"模式
2. 向量化：选择合适的Embedding模型
3. 检索策略：向量检索 + 全文检索混合
4. 重排序：根据相关性和时效性排序
```

**知识库配置（Dify参考）**：
- 支持多格式文档（PDF、CSV、Word等）
- 支持连接外部数据源
- 配置向量检索、全文检索等算法

### 3.2 工具调用（Tool Use）

**核心工具类别**：

| 类别 | 工具示例 | 用途 |
|------|----------|------|
| 数据获取 | Web Scraper、API Caller | 网页抓取、接口调用 |
| 文档处理 | PDF Parser、Excel Handler | 文档解析与处理 |
| 计算分析 | Python Executor | 因子计算、数据分析 |
| 通讯推送 | Email Sender、Webhook | 结果推送与通知 |

**工具复用机制**：
- 将常用工作流打包为工具
- 支持嵌套调用
- 减少重复开发

### 3.3 自动化排版

**Python实现方案**：
```python
# 核心库
from docx import Document  # Word
from pptx import Presentation  # PPT
import pandas as pd  # Excel/表格
import matplotlib.pyplot as plt  # 图表

# 功能模块
- 文本样式设置
- 表格插入与格式化
- 图表生成与导出
- 模板套用与替换
```

**最佳实践**：
- 预设模板库，保持风格统一
- 数据与模板分离，便于维护
- 支持批量生成

## 四、投研场景应用

### 4.1 定期报告自动生成

**任务拆解（五类任务）**：

| 任务类型 | 处理方式 | 关键技术 |
|----------|----------|----------|
| 市场数据点评 | 结构化数据 + 提示词 | 数据清洗、格式化输出 |
| 热点新闻点评 | RAG检索 + 大模型生成 | 新闻召回、观点提炼 |
| 观点输出 | 研报素材 + 逻辑整合 | 观点提取、逻辑串联 |
| 固定格式输出 | 模板填充 | 模板引擎 |
| 图表输出 | 数据可视化 | matplotlib/echarts |

**效率提升**：
- 周报生成时间：4小时 → 30分钟
- 数据准确性提升
- 格式统一规范

### 4.2 公告监控与处理

**实现流程**：
```
定时抓取 → 目标筛选 → PDF解析 → 摘要生成 → 推送通知
```

**效果指标**：
- 处理时间：2小时 → 15分钟
- 关键信息提取准确率：95%+
- 支持自定义关注维度

### 4.3 个股分析报告

**报告结构模板**：
```markdown
## 1. 公司概况
- 基本信息、主营业务、行业地位

## 2. 财务分析
- 营收、利润、ROE、现金流等核心指标
- 趋势分析与同行对比

## 3. 估值对比
- PE/PB/PS等估值指标
- 历史分位与行业对比

## 4. 风险提示
- 经营风险、政策风险、市场风险

## 5. 投资建议
- 综合评估与操作建议
```

### 4.4 研报复现

**核心价值**：
- 研报方法论可复用
- 历史分析可追溯
- 支持批量回测验证

**实现步骤**：
1. 解析研报分析框架
2. 提取关键计算逻辑
3. 封装为参数化Skills
4. 支持换股票/换时间复现

## 五、提示词工程

### 5.1 提示词设计框架

```
【角色设定】
你是一位专业的金融分析师...

【任务描述】
请根据以下数据，撰写市场点评...

【输入数据】
{结构化数据}

【输出要求】
1. 格式要求：...
2. 字数限制：...
3. 重点关注：...

【输出示例】
{示例文本}

【注意事项】
- 数据来源需标注
- 观点需有数据支撑
- 避免绝对化表述
```

### 5.2 关键要素

| 要素 | 说明 | 重要性 |
|------|------|--------|
| 角色设定 | 明确Agent身份和专业领域 | ★★★★★ |
| 任务描述 | 清晰定义任务目标和边界 | ★★★★★ |
| 输出示例 | 提供期望输出的范例 | ★★★★☆ |
| 注意事项 | 规避常见错误和风险 | ★★★★☆ |
| 格式约束 | 规定输出结构和格式 | ★★★☆☆ |

### 5.3 迭代优化

**持续改进机制**：
1. 记录每次分析的输入输出
2. 基于反馈自动优化提示词
3. 版本控制与回滚机制
4. A/B测试对比效果

## 六、Agent设计模式

### 6.1 投资大师Agent（AI Hedge Fund模式）

**设计理念**：将投资大师的投资理念转化为AI Agent

**11位投资大师框架**：

| 大师 | 风格 | 核心逻辑 | 适用场景 |
|------|------|----------|----------|
| 巴菲特 | 价值投资 | 护城河、安全边际 | 蓝筹股筛选 |
| 彼得·林奇 | 成长投资 | PEG估值、十倍股 | 成长股挖掘 |
| 格雷厄姆 | 深度价值 | 净净值投资 | 低估值筛选 |
| 索罗斯 | 宏观投机 | 反身性理论 | 宏观择时 |
| 达里奥 | 全天候 | 风险平价 | 资产配置 |

**A股适配要点**：
- 替换国内数据源（Wind、iFinD）
- 适配A股财务报表格式
- 考虑A股市场特点（散户占比、涨跌停等）
- 调整估值体系

**回测效果（彼得·林奇风格）**：
- 2022-2025年跑赢沪深300
- 2025年超额收益9.99%

### 6.2 思维链决策Agent（CoT模式）

**核心机制**：
```
信息采集 → 假设验证 → 推理生成 → 结论输出
```

**投资框架设计示例（医药行业）**：

| 核心假设 | 验证维度 | 数据来源 |
|----------|----------|----------|
| 创新药管线是估值驱动力 | 管线数量、临床进展 | CDE、公司公告 |
| 政策影响盈利预期 | 医保谈判、集采情况 | 政策文件、财报 |
| 海外拓展打开空间 | FDA批准、海外收入占比 | 公告、财报 |

**输出格式**：
```
【投资思维链 - XXX公司】

假设1验证：创新药管线
- 事实：[具体数据]
- 验证结果：✓ 强支撑 / ○ 中性 / ✗ 不支撑

假设2验证：政策影响
- 事实：[具体数据]
- 验证结果：✓ / ○ / ✗

综合评估：买入/持有/卖出（置信度：XX%）
核心逻辑：[一句话总结]
风险提示：[关键风险]
```

### 6.3 多Agent协作模式

**投票机制**：
- 构建多个独立的投资思维链（不同假设框架）
- 每个思维链独立给出投资建议
- 通过投票机制综合判断

**回测效果**：
- 年化超额收益：17.16%
- 信息比率：0.48
- 最大回撤：-18.5%（基准-35.2%）

### 6.4 专业化分类Agent

**问题范畴划分**：
```
用户问题 → 范畴识别 → 调用对应Agent
              ↓
    ┌─────────┼─────────┐
    ↓         ↓         ↓
  个股Agent  行业Agent  宏观Agent
    ↓         ↓         ↓
  专属知识库  专属知识库  专属知识库
```

**每个Agent配置**：
- 专属知识库
- 专属工具集
- 定制化提示词

## 八、最佳实践

### 8.1 投研Agent搭建清单

**第一阶段：基础能力**
- [ ] 选择并部署大模型（推荐DeepSeek）
- [ ] 搭建开发平台（Dify或OpenClaw）
- [ ] 接入核心数据源（行情、财务、新闻）
- [ ] 构建基础知识库（研报、公告）

**第二阶段：场景落地**
- [ ] 实现定期报告自动生成
- [ ] 实现公告监控与摘要
- [ ] 实现个股分析报告
- [ ] 实现新闻热点点评

**第三阶段：高级功能**
- [ ] 构建投资大师Agent
- [ ] 实现思维链决策机制
- [ ] 实现多Agent协作投票
- [ ] 实现研报复现与回测

### 8.2 关键成功因素

| 因素 | 说明 | 建议 |
|------|------|------|
| 数据质量 | 信息来源可靠性 | 接入专业数据源 |
| 提示词工程 | 输出质量关键 | 持续迭代优化 |
| 模块化设计 | 可维护性 | Skills解耦、复用 |
| 人机协作 | 效率与质量平衡 | 关键环节人工审核 |

### 8.3 常见问题与解决方案

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 幻觉问题 | 模型编造事实 | RAG检索增强、来源标注 |
| 数据时效 | 信息过时 | 定时更新、实时接口 |
| 格式不一致 | 提示词不够明确 | 增加输出示例、格式约束 |
| 观点偏差 | 单一信息源 | 多源交叉验证 |

### 8.4 合规与风险

**可审计性要求**：
- 所有操作可追溯
- 决策逻辑可复现
- 数据来源可查证

**风险提示**：
- 回测结果不代表未来收益
- AI输出需人工审核
- 投资决策最终由人做出
